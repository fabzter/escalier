## Text and action policy (G-10/G-11)

- Exactly one action for an initial selected physical shortcut down; consume its repeats and matching up without firing more actions. Reserved action matching precedes text capture.
- Text capture is a separately explicit mode, never the startup/default mode. It consumes printable Unicode supplied by the native API only after gating. Bound each extraction to 128 UTF-16 units, total retained text to 1024 units, and never split a Unicode scalar when truncating. Mark overflow/truncation; do not grow or silently declare exact text success.
- Backspace removes the previous complete scalar/grapheme according to the implementation's documented policy; forward Delete has a separately documented end-of-buffer no-op policy. Both are consumed when text mode is armed.
- Return and Tab are consumed, not inserted; arrows, Home/End, PageUp/PageDown are consumed and ignored. Record navigation counters and verify no field focus/scroll change in the runtime matrix. Escape is consumed as emergency stop only while actively armed; during OFF it passes. Its own down/up ownership follows the same bounded-drain rule.
- Unknown controls and command/control/option combinations not registered as actions pass without text extraction. Shifted printable input is permitted. Pure modifiers pass. US-layout simple Unicode is the initial supported manual probe; IME, dead keys and composition correctness remain NOT IMPLEMENTED/NOT PROVEN.

## Rulings

- Ruling: reject the review's special-event mask bits and repeat reference-count/modifier-tuple suggestions — special disabled notifications are not mask indices, and repeats have one eventual physical keyup — cost if wrong: the native adapter or pairing tests need correction before runtime.
- Ruling: drain is finite and a pending key at teardown invalidates the case, rather than promising future suppression after removal — keeps global input restoration bounded — cost if wrong: some held-key scenarios remain unproven and require a different production design.
- Ruling: callback work has explicit finite bounds and an invalidation threshold, not an unverified no-allocation/hard-real-time claim — avoids false performance assurance from headless tests — cost if wrong: runtime callback performance may require a lower-level implementation.

## Focus-scope clarification after initial task review

- The prompt-free native focus gate in this bounded fixture is **foreground-application PID**, as in G-02 arming/G-06/G-07. It is not a DOM/page/editable-field focus monitor and must not be described as automatically detecting all same-PID focus changes.
- Page/field focus, visibility and the SAME-chord OFF delivery control remain independent browser/manual acceptance preconditions. Failure is INVALID, requires immediate manual Stop, and cannot be relabelled as native automatic disarm. Use only the dedicated throwaway browser process containing the inert synthetic fixture, never private inputs or general browsing.
- Ruling: make the native app-focus versus browser-field focus boundary explicit instead of introducing new AX/DOM surveillance into this PID-scoped probe — the binding implementation gate already specifies foreground PID and the browser oracle separately verifies field focus — cost if wrong: same-PID page/field focus loss can leave the tap armed until manual Stop or the existing bounded timeout; automatic same-PID focus enforcement remains NOT IMPLEMENTED and must be disclosed before any runtime approval.
