Window, focus and receiver-capture harness

This local page is a manual test surface for a synthetic AppKit fixture and a browser sender/receiver pair. It exists to record what a receiver actually decoded, not to establish invisibility. A sender preview is never receiver evidence.

Manual protocol

  1. Start the local server yourself: node tools/serve-local.mjs --port 8642.
  2. Prepare a clean Space/display: close private windows, silence notifications, and remove unrelated content.
  3. Open the sender and receiver pages in separate tabs.
  4. Choose the capture source yourself in the browser picker. Grant any browser or macOS screen-recording permission yourself.
  5. Stop sharing, revoke permission when finished, and keep this window plus the native stop/close controls reachable.

The fixture never starts a server, opens a browser, selects a picker item, grants a permission, uses a microphone, or records a full frame. Only video receiver metadata and explicitly cropped marker ROI samples are read.

Evidence boundaries

  • Sharing-none is a legacy window flag; the fixture records it but does not treat it as a modern capture guarantee.
  • A sharing-readOnly control must be positively visible in the same cell before a sharing-none marker absence is interpreted.
  • A selected external window with both markers outside the source is N/A, not evidence of exclusion.
  • Entire-display and selected-window capture are different surfaces and must be recorded separately.
  • A synthetic local result says nothing about undisclosed HackerRank or other third-party signals.
