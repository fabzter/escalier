The test suite pins those disclaimers. The user-approved addition is labelled honestly; it is not presented as a reproduction of the owner's Handy observation.

## Notes, not defects

- **SPEC value-domain note (coordinator-owned).** SPEC.md's manifest example only shows single-language entries. `mixed`/`auto` is accepted by `manifest_tools` and by the runner (and tested there), but the authoritative SPEC should record the extension in one sentence so the contract is not implicit. This is the only reason the spec verdict carries a caveat.
- **`es_419` vs `es-US`.** The dataset locale is `es_419` while the ASR hint is `es-US`. SPEC's own example uses `es-US`, and Nemotron offers `es-US`/`es-ES` rather than `es_419`; the manifest records both fields separately. The choice is defensible and recorded, but the report/README should say it is a model-prompt choice, not a claim that FLEURS `es_419` is `es-US`.
- **Red evidence is import-error red.** The report's red run failed with `ModuleNotFoundError` rather than behavioral assertions. Green coverage is real and the red state was expected; this is weaker TDD evidence, not a correctness issue.
- **Preflight said FLEURS was already PCM16.** The implementation found 32-bit IEEE-float members and documented a stdlib conversion. The cached source sizes (276,538 and 361,018 bytes) and the successful frame-count checks support the report, so the implementation is right and the earlier preflight assumption was stale.
- **Attribution is sufficient.** CC-BY-4.0 notice, attribution, license link, change description and no-endorsement statement are present. No separate third-party notice for the underlying FLoRes text is present; the dataset card's CC-BY-4.0 attribution is the controlling one for this small slice.
